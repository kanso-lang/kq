# Retired instructions, counted by callgrind on the linux runner. The vein the
# allocator counters cannot reach: both quadratics behind the 147 ms row
# allocated nothing new, so every other gate in this repo stayed green across a
# 3.7x change in the published number.
#
# Which runner, made checkable. bench/instructions.sh reads the line below and
# refuses to measure anywhere else, because the sentence above it is a rule
# that nothing enforced: kanso pasted a container's numbers over its runner's
# on 2026-08-23 on the strength of a diff, and two ubuntu 24.04 boxes one glibc
# revision apart differ by more than most of what this vein catches.
# measured-on glibc=2.39-0ubuntu8.8
#
# Watched, not frozen. A rise is a regression to explain and a fall is a win to
# bank; moving the pin moves these rows and that is the point of having them.
# Say which way and why in the PR, then regenerate.
#
# The big fixture is ten flat copies of bench/large.json, so a row that is
# linear in the input lands near 10x its small sibling. Both do, which is the
# same thing bench/scale_gate.kso asserts about the allocator counters and the
# first time it has been asserted about work:
#
#   print  793,574,242 / 78,436,396 = 10.12x
#   path   218,906,819 / 21,300,482 = 10.28x
#
# First sitting 2026-08-14, against the compiler in .kanso-version — the pin
# carrying kanso #895 and #888, the two fixes that took the print row from
# 147 ms to 39.8 ms.
# 2026-08-20: every row falls under the pin bump c7f302c6 -> cc26898a —
# print_small -331,611 (-0.4%), print_big -2,256,286 (-0.3%), path_small
# -304,464 (-1.4%), path_big -2,243,856 (-1.0%). Forty kanso commits moved
# codegen (the alternating fixpoint sweep among them); the surrogate
# machinery this PR adds runs only on `\u` escapes, which these inputs do
# not contain. Banked, not explained row by row.
# 2026-08-20 (shorthands): print rows split — print_small falls 340 (two
# fewer frozen startup constants) while print_big pays 12,078 for the two
# new jump-table arms its escape-heavy output compares against; both path
# rows fall by ~1,300. Net well under a thousandth of a percent per row.
# 2026-08-20 (the literal is the number): both path rows fall ~4.1% —
# decode no longer parses a single float, so Eisel-Lemire's work leaves
# the path entirely — while print_big pays 1.44M (+0.18%) for the GDA
# reassembly of exponent-marked literals and print_small nets slightly
# down. The trade the change makes: decode cheaper, print marginally
# dearer, and every byte identical to jq.
# 2026-08-23: every row falls under the pin bump cc26898a -> 2601a7a5, and the
# shape says where it comes from. The small rows each lose 6,250 and the big
# rows each lose 62,500 — ten times over, matching the ten copies the big
# fixture is made of — and print and path lose the same amount as each other.
# A cost that scales with the input and is identical across the two operations
# lives in the reading and decoding they share.
#
# That rules out the change the window is named for. Eleven kanso commits are
# in it, the std/os split among them, and the split saves module-init work done
# before any input is read. This file has twice established that such a saving
# lands as a flat offset across fixtures of very different sizes, and a flat
# offset cannot present as a 10x spread. Banked without a row-by-row account,
# with the shape recorded so the next reader starts at the input path.
# 2026-08-15: all four rows rise, 0.12% to 0.35%. The pin walks twenty
# commits forward and what it collects is kanso's escaped-buffer registry
# (kanso#912), which every program links whether or not it grows an
# accumulator past its beat. kanso's own vein recorded the same band on its
# six benchmarks. kq's allocator counters move the other way over the same
# window — evacuations 989 to 533, evacuated bytes 488,624 to 395,376 — and
# this vein cannot see that, which is the division of labour between the two.
# 2026-08-17: all four rows rise by EXACTLY 74 instructions, and the constant
# is the finding. print_big does forty times the work of path_small and pays
# the same 74, so this is a fixed cost per run rather than a cost per row —
# 0.00009% on the big print and 0.0003% on the small path.
#
# The pin walks eleven commits to kanso cd1142e7, carrying gavel 20 (a
# guarded self-reference completes at its constructor) and 20b's cycle guard.
# What kq collects is the completion itself: k_caf_complete now answers the
# seed cell with the frozen value, which is a couple of stores per constant,
# paid once at k_caf_init before any input is read. The render guard it also
# carries is a test per FORCED CELL rendered, and kq renders none — which is
# exactly why these rows show a flat offset instead of one that grows with
# the output.
#
# kanso's own vein recorded +74 on encodebench and widebench over the same
# window, the same number for the same reason.
# 2026-08-17 (later): all four rows FALL by exactly 18, and the constant is
# again the finding. print_big does forty times the work of path_small and
# collects the same 18, so this is a fixed cost per run rather than per row.
#
# The pin carries gavel 20b's second half: rendering forces what it prints
# and a container goes on the render path. The prediction written into the
# PR was that kq would RISE, because it renders on every row it prints and
# the container path is paid per rendered container. That prediction is
# wrong and the direction is the evidence — a per-row cost cannot show up as
# a flat offset across fixtures forty times apart.
#
# What the rows actually collect: k_render's thunk arm lost its early-out
# and now forces, but kq renders no cell that has not run, so that branch is
# never taken and nothing per-row changes. Eighteen instructions of layout
# around code the linker places differently, in kq's favour this time.
# kanso's own vein recorded -18 on encodebench, oneshot and widebench over
# the same window, the same number for the same reason.
#
# 2026-08-26: all four rows RISE, and unlike every entry above this one the
# rise is proportional to the DOCUMENT rather than flat.
#
#     print_small  78,370,357 ->  78,758,842   +388,485   +0.50%
#     path_small   20,172,881 ->  20,560,668   +387,787   +1.92%
#     print_big   793,645,399 -> 797,583,853 +3,938,454   +0.50%
#     path_big    208,407,698 -> 212,343,588 +3,935,890   +1.89%
#
# print and path collect the SAME number on the same fixture — 388k on the
# small one, 3.94M on the big — so the cost is in the decode both share and
# not in printing or in path extraction. It is ten times larger on the ten
# times larger document, which is what a per-element cost looks like.
#
# Most of it is kanso gavel 24: an arm cannot see an err its own hako raised,
# and that is dispatch semantics, so an arm that could match its own hako's
# failure asks before it matches, every time it runs. Measured rather than
# inferred, by building this repo against kanso main with the ruling and
# against main without it, on one host so the glibc offset cancels:
#
#     print_small  78,409,395 -> 78,758,433   +349,038
#     path_small   20,211,413 -> 20,560,255   +348,842
#
# So gavel 24 is about 349k of the 388k, and the remaining 39k is the rest of
# the twenty merges this pin bump absorbs. The allocator counters are the
# other half of the story and they FELL — the guard allocates nothing, which
# is exactly why this vein exists and why cost_golden could not see it.
#
# kanso's own vein recorded the same shape on the same day: jsonbench +1.81%,
# oneshot +0.74%, and three benchmarks whose hot paths hold no err-admitting
# arm did not move at all.
