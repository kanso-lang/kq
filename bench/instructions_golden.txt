# Watched, not frozen. A rise is a regression to explain and a fall is a win to
# bank; moving the pin moves these rows and that is the point of having them.
# Say which way and why in the PR, then regenerate.

# 2026-08-15: all four rows rise, 0.12% to 0.35%. The pin walks twenty
# commits forward and what it collects is kanso's escaped-buffer registry
# (kanso#912), which every program links whether or not it grows an
# accumulator past its beat. kanso's own vein recorded the same band on its
# six benchmarks. kq's allocator counters move the other way over the same
# window — evacuations 989 to 533, evacuated bytes 488,624 to 395,376 — and
# this vein cannot see that, which is the division of labour between the two.
# 2026-08-17: all four rows rise by EXACTLY 74 instructions, and the constant
# is the finding. print_big does forty times the work of path_small and pays
# the same 74, so this is a fixed cost per run rather than a cost per row —
# 0.00009% on the big print and 0.0003% on the small path.
#
# The pin walks eleven commits to kanso cd1142e7, carrying gavel 20 (a
# guarded self-reference completes at its constructor) and 20b's cycle guard.
# What kq collects is the completion itself: k_caf_complete now answers the
# seed cell with the frozen value, which is a couple of stores per constant,
# paid once at k_caf_init before any input is read. The render guard it also
# carries is a test per FORCED CELL rendered, and kq renders none — which is
# exactly why these rows show a flat offset instead of one that grows with
# the output.
#
# kanso's own vein recorded +74 on encodebench and widebench over the same
# window, the same number for the same reason.
# 2026-08-17 (later): all four rows FALL by exactly 18, and the constant is
# again the finding. print_big does forty times the work of path_small and
# collects the same 18, so this is a fixed cost per run rather than per row.
#
# The pin carries gavel 20b's second half: rendering forces what it prints
# and a container goes on the render path. The prediction written into the
# PR was that kq would RISE, because it renders on every row it prints and
# the container path is paid per rendered container. That prediction is
# wrong and the direction is the evidence — a per-row cost cannot show up as
# a flat offset across fixtures forty times apart.
#
# What the rows actually collect: k_render's thunk arm lost its early-out
# and now forces, but kq renders no cell that has not run, so that branch is
# never taken and nothing per-row changes. Eighteen instructions of layout
# around code the linker places differently, in kq's favour this time.
# kanso's own vein recorded -18 on encodebench, oneshot and widebench over
# the same window, the same number for the same reason.
